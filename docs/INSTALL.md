# Installing Cosmic Pulse

Three ways to run Pulse on a Linux PC. All are **local-only** — no cloud, no account.

## Requirements

- Linux with `/proc` and `/sys`
- **Python 3.11+**
- **python3-venv** (recommended for `install.sh`; script falls back to system Python if missing)
- pip packages: `psutil`, `PyYAML` (or distro packages `python3-psutil`, `python3-yaml`)

On Pop!_OS / Ubuntu, apt packages are enough (no pip required):

```bash
sudo apt install python3-psutil python3-yaml
# optional, for venv-based install:
sudo apt install python3-venv python3-pip
```
- Optional: Steam (for game-aware features). Temps/fans come from `/sys/class/hwmon` — `lm-sensors` is not required.

## Option 1 — Install script (recommended)

From a git clone or extracted tarball:

```bash
git clone https://github.com/tramonkamble/cosmic-pulse.git
cd cosmic-pulse
chmod +x install.sh
./install.sh --service
```

This copies the app to `~/.local/share/cosmic-pulse`, creates a venv, installs `~/.local/bin/cosmic-pulse`, and optionally enables a **user** systemd service.

| Flag | Meaning |
|------|---------|
| `--service` | `systemctl --user enable --now cosmic-pulse` |
| `--dir PATH` | Custom install directory |
| `--port 8765` | HTTP port (`PULSE_PORT`) |
| `--system-python` | Skip venv; `pip install --user` |
| `--uninstall` | Remove install, wrapper, and service |

Open **http://localhost:8765**.

Ensure `~/.local/bin` is on your `PATH`.

## Option 2 — Manual / development

```bash
git clone https://github.com/tramonkamble/cosmic-pulse.git
cd cosmic-pulse
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 server.py
```

State files (`pulse.db`, `.pulse_config.json`, …) are created in the repo directory.

Copy `.pulse_config.example.json` to `.pulse_config.json` if you want an explicit config file.

## Option 3 — Debian package (.deb)

Build on the target machine (or CI):

```bash
chmod +x deploy/build-deb.sh
./deploy/build-deb.sh
# → build/deb/cosmic-pulse_0.1.0_all.deb
```

Install:

```bash
sudo apt install ./build/deb/cosmic-pulse_0.1.0_all.deb
systemctl --user daemon-reload
systemctl --user enable --now cosmic-pulse
```

The package installs read-only files under `/usr/lib/cosmic-pulse/`. Writable state goes to **`~/.local/share/cosmic-pulse`** automatically (see `paths.py`).

Dependencies are pulled via apt: `python3`, `python3-psutil`, `python3-yaml`.

## systemd user service

Template units:

- **User install:** generated by `install.sh` at `~/.config/systemd/user/cosmic-pulse.service`
- **Deb install:** `/usr/lib/systemd/user/cosmic-pulse.service`

```bash
systemctl --user status cosmic-pulse
journalctl --user -u cosmic-pulse -f
systemctl --user restart cosmic-pulse
```

User services start at login. For start-at-boot without login, enable lingering:

```bash
loginctl enable-linger "$USER"
```

## Uninstall

**Install script:**

```bash
./install.sh --uninstall
```

**Deb:**

```bash
systemctl --user disable --now cosmic-pulse
sudo apt remove cosmic-pulse
rm -rf ~/.local/share/cosmic-pulse   # optional — keeps your DB/history
```

## LAN access

By default Pulse binds to `0.0.0.0:8765` so a phone or second machine on the same network can view the dashboard. There is no authentication — use only on trusted networks.

Override port: `PULSE_PORT=9090 cosmic-pulse`

## Troubleshooting

| Problem | Check |
|---------|--------|
| `cosmic-pulse: command not found` | `export PATH="$HOME/.local/bin:$PATH"` |
| Service fails immediately | `journalctl --user -u cosmic-pulse -n 30` |
| Missing GPU sensors | AMD `card1` assumed; see `docs/REVIEW.md` |
| Empty Guidance | Wait a few sampler ticks; run **Scan** on Guidance tab |

See also [ARCHITECTURE.md](ARCHITECTURE.md) for data directories and config files.
